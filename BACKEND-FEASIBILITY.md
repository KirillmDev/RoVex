# RoVex backend feasibility

Pricing checked November 26, 2026, in USD. All figures are monthly estimates for a hypothetical service. Current RoVex uses browser-local storage and existing Roblox services. Its own infrastructure cost is $0. This phase does not create infrastructure.

## Future design, contingent on authorized data

The browser separates the current public server directory from future providers. A future read endpoint, for example GET /v1/places/{placeId}/servers?cursor=…, would return a versioned page, observation timestamp and coverage type. Allowlisted fields would include instance ID and occupancy. Region, version and observed duration would be optional, carry provenance and expire independently. An opaque cursor and a hard batch size protect both provider and clients. Missing data or errors must leave native Play and the direct Roblox occupancy listing available.

- **Data ingestion.** Begin only with a service Roblox documents for the intended access or an explicitly authorized creator-supplied feed. A collector would batch bounded refreshes for opted-in places and stop on quota errors. There is no budget estimate for acquiring rights to data when a source is unavailable.
- **Database.** Use a keyed snapshot table with place ID, instance ID, source, observation/expiry timestamps and nullable authorized metadata. Index by (place ID, observed time) and expiry; use a separate daily aggregate table only if history is approved. Limit hot retention to 24 hours, optionally retain compact aggregates for 30 days. Measure row/index size, IOPS, cursor p95 and expiry lag. A write-heavy history stream would need a separate measured ingestion budget.
- **Cache and freshness.** Cache common public responses for 15–60 seconds. Show the last observation timestamp. Expire metadata if its source stops, and fall back to occupancy. Use single-flight refresh, backoff for upstream 429, bounded pagination and per-place/per-client rate caps. Drop stale snapshots instead of silently presenting them as current.
- **Privacy and operations.** Do not collect Roblox cookies, invitation tokens, player lists, financial activity or IPs in the application dataset. Keep aggregate service metrics and short-lived redacted logs. Add anomaly alerts, least-privilege collector credentials, and a kill switch for upstream and billing thresholds. Treat backups, restore exercises and regional failover as separate approval items.

## Monthly cost model

Monthly active users (MAU) are distinct people using the feature in a 30-day month. The baseline assumes 20 requests, 3 CPU ms per request, 20 indexed rows read per request, 5 billable writes per user (including indexes), and 0.25 GB fixed plus 30 kB indexed hot data per user. The stress case assumes 100 requests, 5 CPU ms, 20 indexed rows per request, 200 writes and 100 kB hot data per user. This is a workload model, not a quota or a forecast of exact capacity.

|       MAU | Baseline requests / writes / storage | Baseline USD | Stress requests / writes / storage | Stress USD |
| --------: | ------------------------------------ | -----------: | ---------------------------------- | ---------: |
|     1,000 | 20k / 5k / 0.28 GB                   |           $0 | 100k / 200k / 0.35 GB              |         $0 |
|    10,000 | 200k / 50k / 0.55 GB                 |           $0 | 1M / 2M / 1.25 GB                  |         $0 |
|   100,000 | 2M / 0.5M / 3.25 GB                  |           $0 | 10M / 20M / 10.25 GB               |      $9.34 |
|   300,000 | 6M / 1.5M / 9.25 GB                  |        $8.19 | 30M / 60M / 30.25 GB               |     $42.34 |
| 1,000,000 | 20M / 5M / 30.25 GB                  |       $27.54 | 100M / 200M / 100.25 GB            |    $262.84 |

The table uses Workers and D1. Free allows 100k requests/day and 10 CPU ms/request plus 5M rows read/day, 100k rows written/day and 5 GB total. The zero-cost rows assume evenly distributed use with enough room for daily peaks. Paid uses a $5 base, $0.30 per million requests over 10M, $0.02 per million CPU ms over 30M, $1 per million writes over 50M and $0.75/GB over 5 GB. Reads remain within the paid allowance under these indexed-query assumptions. Plan per-database capacity and partition by place before approaching database size or write-throughput limits. A 100k-MAU baseline could still require the paid $5 plan during a peak. Allow a contingency based on observed usage before committing to any budget. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) · [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) · [D1 limits](https://developers.cloudflare.com/d1/platform/limits/)

As a PostgreSQL option, Neon Free offers a small per-project storage and compute allowance for a prototype. On Launch, the published $0.106/CU-hour and $0.35/GB-month imply about $22.58/month for a hypothetical 0.25 CU active 730 hours and 9.25 GB and excluding API hosting and network overages. On larger loads, benchmark connection pooling, concurrent writes and retention before selecting compute. R2 Standard object storage can hold approved aggregate exports at $0.015/GB-month beyond the free allowance, plus operations. It is not needed for the hot relational index. [Neon pricing](https://neon.com/pricing) · [R2 pricing](https://developers.cloudflare.com/r2/pricing/)

Estimates exclude tax, a domain, external data/license costs, backups beyond plan allowances, logs, vendor transfer overages, staffing, and on-call work. A 2 kB compressed response would return roughly 40 GB/month at 20M requests. Establish a data source and measure upstream limits before pricing availability, history depth, or regional coverage.
